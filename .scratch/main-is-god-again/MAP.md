# Main is God again

## Destination

`feature/0.3/embeds` (this spine) is merged into `main` **without a release tag**. `main` holds respectable, non-broken, security- and architecture-reviewed code that matches the single-model product; thin working docs describe how we change the project going forward; a **Known issues** list holds non-blocking debt; stale branches are deleted after an approved checklist. Public tagging / website download is explicitly a later effort.

## Notes

- **Domain:** Capture + Notes + anonymous speakers/names. Speakers matter for future context packs (who spoke before what was said); rename cascades across that speaker’s turns in a note.
- **Tracker:** Local markdown — see `docs/agents/issue-tracker.md` → Wayfinding operations.
- **Quality stance:** Human is product conscience and not a hardened engineer; agents must use written rubrics and evidence. Unease + a real finding ⇒ merge-blocker. “Just get it done” is not a resolution.
- **Skills:** `/grilling`, `/domain-modeling`, security-review / architecture review passes, `/research`-style sweeps when resolving research tickets. After the map clears → `/to-spec` (not straight to `/implement` for the whole destination).
- **Platform care:** Apple Silicon is what we exercise for confidence. Intel is not a focus of this map.
- **Known issues:** Capture freely in [`KNOWN-ISSUES.md`](./KNOWN-ISSUES.md); promote to implementation tickets only when sharp.
- **Niggle pass:** Screen/workflow walk with a live Record (or Dictate→note) and spoken narration; share the note with the agent; triage into Known issues vs merge-blockers. Complements *Silicon ship-bar smoke*, does not replace the sort-findings grilling.
- **Session bridge:** Resume via [`HANDOFF.md`](./HANDOFF.md) — do not rely on chat memory.
- **Refer by name:** Always use ticket titles in narration.

- [Reorder startup sequencing](./issues/z_24-reorder-startup-sequencing.md) — **closed**, then **corrected**: `create_tray` now runs right after hotkeys/settings resolve. First pass wrapped the model-seed loop in a bare `async_runtime::spawn` — its synchronous file I/O starved the async runtime's worker pool, so opening the main window right after the tray appeared queued behind it (human-observed: 16+ second skeleton, instant if you waited ~30s first). Fixed by switching to `tokio::task::spawn_blocking`, the pattern already used everywhere else in this codebase for sync work. `prewarm_dictate_window` left synchronous (main-thread-only API, didn't gate tray anyway).
- [Eagerly preload Whisper at startup](./issues/z_39-eager-preload-whisper-at-startup.md) — **closed**: human noted the first Dictate press of a session still pays a cold-load cost even after ticket 30, and asked why the ~181 MB Whisper Small context isn't just kept warm — it's cheap enough to justify it. Added `model_seed_bg.preload_context(...)` inside the same (now correctly `spawn_blocking`) startup task, right after the seed loop confirms the model file is healthy. VAD and Sortformer intentionally not eagerly preloaded (VAD trivial per-call cost; Sortformer large and Dictate-irrelevant).
- [Cache VAD hash fingerprint](./issues/z_25-cache-vad-hash-fingerprint.md) — **closed**: new `dest_needs_bundle_restore_cached` in `bundled_models.rs` (mtime+size+expected-sha sidecar cache), wired into the VAD startup check. Built generically so [Cache Whisper hash](./issues/z_36-transcribe-cache-whisper-hash.md) can reuse it.
- [Parallelize Sortformer load](./issues/z_35-transcribe-parallelize-sortformer-load.md) — **closed**: implemented via `std::thread::scope` in `run_post_capture_transcription_with_inference` — Sortformer's on-demand diarize pass now runs on a scoped thread concurrently with the ASR pass instead of strictly after, since it shares no lock with `ModelService.inference_gate` (unlike ticket 34's case). Performance win is unverified (no real models/hardware in this environment to profile); correctness verified via existing tests.
- [Cache Whisper hash](./issues/z_36-transcribe-cache-whisper-hash.md) — **closed, already solved**: `ModelService::model_integrity_ok_cached` (in-memory mtime+size cache) already exists on `release/0.3` and is already wired into `transcribe_pcm_with_progress` — this must have landed independently since the ticket's stale research base. No code changed.
- [Prefetch next decode](./issues/z_37-transcribe-prefetch-next-decode.md) — declined: overlapping next-item decode with the current item's inference needs a real pipeline restructure (prefetch failure handling, cancellation semantics), with an expected win capped by decode time (likely small next to Whisper+diarization per item) and no real audio/models available here to measure or verify it. Revisit with real batch timing data first.
